# Як отримати APK і встановити застосунок на телефон

Ця інструкція веде від папки з проєктом до працюючого «Трекера сну» на вашому Android-телефоні. Знати Android чи програмування не потрібно: усе робиться кількома командами в терміналі та кількома натисканнями на сайті expo.dev.

**Як це працює.** Телефон не вміє перетворити вихідний код на програму. Це робить безкоштовний хмарний сервіс Expo — EAS Build: ви відправляєте йому проєкт, за 10–60 хвилин отримуєте готовий файл `.apk` і встановлюєте його на телефон так само, як будь-яку програму. Android Studio на комп’ютері не потрібна.

> **Чесне застереження.** Код перевірено автотестами (94 тести логіки й бази даних) і в браузерному стенді, що імітує екран телефона. Але в середовищі, де писався застосунок, не вдалося встановити справжні пакети Expo / React Native й запустити його на реальному телефоні. Тому під час першої збірки можливі дрібні проблеми (наприклад, версії пакетів). Крок 3 нижче якраз для цього; а якщо збірка зупиниться з помилкою — скопіюйте кінець її журналу й надішліть у чат, помилку виправимо (див. розділ «Якщо щось пішло не так»).

## 0. Що потрібно підготувати

| Що | Деталі |
|---|---|
| Комп’ютер | Windows 10/11, macOS або Linux з доступом до інтернету |
| Node.js | версія **22.13 або новіша** (підійде поточна LTS) — завантажте з [nodejs.org](https://nodejs.org). Перевірка: `node -v` |
| Акаунт Expo | безкоштовний, реєстрація на [expo.dev/signup](https://expo.dev/signup) (потрібна електронна пошта; підтвердіть її з листа) |
| Телефон | Android 7.0 або новіший |
| Час | перша збірка — від 20 хвилин до години (більшість часу — черга безкоштовного плану) |

Платити нічого не потрібно. Акаунт розробника Google Play (25 $) потрібен лише для публікації в магазині — для встановлення на власний телефон він не потрібен.

## 1. Розпакуйте проєкт і відкрийте термінал

1. Розпакуйте архів `sleep-tracker.zip` у будь-яку папку, наприклад `Документи\sleep-tracker`.
2. Відкрийте термінал **у цій папці**:
   - **Windows 11:** у Провіднику відкрийте папку `sleep-tracker`, клацніть правою кнопкою на порожньому місці й оберіть «Відкрити в Терміналі».
   - **Windows 10:** у Провіднику відкрийте папку, у рядку адреси напишіть `cmd` і натисніть Enter.
   - **macOS:** Термінал → `cd ` і перетягніть папку у вікно → Enter.
3. Перевірте, що Node.js встановлено:

   ```bash
   node -v
   ```

   Має показати `v22.13.0` або вище. Якщо версія нижча, встановіть новішу з [nodejs.org](https://nodejs.org) і відкрийте термінал заново.

> **Windows PowerShell:** якщо замість результату бачите «running scripts is disabled on this system», виконайте один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` і підтвердіть. Або користуйтеся звичайною командною стрічкою (`cmd`) — там цієї проблеми немає.

## 2. Встановіть залежності

```bash
npm install
```

Команда завантажить усі потрібні бібліотеки у папку `node_modules` (2–5 хвилин). Це нормально, якщо з’являться жовті попередження (`npm warn`). Червоні помилки (`npm error`) — див. [«Якщо щось пішло не так»](#якщо-щось-пішло-не-так).

## 3. Узгодьте версії пакетів з Expo

```bash
npx expo install --fix
npx expo-doctor
```

- **Перша команда** сама підбирає для вашого Expo SDK 57 точні сумісні версії всіх пакетів і змінює їх у `package.json`. Версії в проєкті записано за документацією, але без реальної перевірки встановленням — тож цей крок страхує від найпоширенішої причини невдалих збірок.
- **Друга команда** перевіряє проєкт на типові проблеми. Якщо вона повідомляє про помилки (✖) — виправте їх за підказками в тексті або надішліть мені їх у чат. Попередження про недоступність мережі чи мовні налаштування можна ігнорувати.

## 4. За бажанням: запустіть автотести

```bash
npm test
```

Очікуваний підсумок: `pass 94`, `fail 0`. Тести перевіряють підрахунок статистики, дати, резервні копії, роботу з базою даних SQLite, ротацію порад тощо. Вони не потрібні для збірки, але підтверджують, що логіка працює на вашій версії Node.

Команда `npm run typecheck` перевіряє типи. Якщо вона покаже помилки типів, це **не** завадить збірці APK (під час збірки типи не перевіряються), але сповістіть мене, я виправлю.

## 5. Задайте власний ідентифікатор застосунку

Кожен Android-застосунок має унікальний ідентифікатор (пакет). У файлі `app.json` він такий:

```json
"android": {
  "package": "com.sleeptracker.app",
```

Для особистого використання можна залишити як є. Але краще замінити на свій, наприклад `com.ivan.sleeptracker` (латинські малі літери, цифри та крапки; мінімум дві частини, кожна починається з літери).

> **Зробіть це до першої збірки.** До ідентифікатора прив’язується ключ підпису. Якщо змінити його пізніше, Android вважатиме новий файл іншим застосунком: він встановиться поруч зі старим, а дані не перенесуться.

## 6. Встановіть EAS CLI й увійдіть в акаунт

```bash
npm install --global eas-cli
eas login
```

`eas login` попросить електронну пошту (або ім’я користувача) і пароль від акаунта Expo. Перевірити, що вхід виконано: `eas whoami`.

Якщо не хочете встановлювати програму глобально, замість `eas …` можна писати `npx eas-cli@latest …` (наприклад, `npx eas-cli@latest login`).

## 7. Запустіть збірку APK
set EAS_NO_VCS=1 - то крч треба кодний раз вводити бро
```bash
eas build --platform android --profile preview
```

Скорочено: `npm run build:apk`.

Профіль `preview` уже налаштовано в `eas.json` так, щоб на виході був саме **`.apk`** (звичайний файл, який можна встановити напряму), а не `.aab` (формат для Google Play, який напряму не встановлюється).

Під час першого запуску термінал поставить кілька запитань:

| Запитання | Відповідь |
|---|---|
| `Would you like to automatically create an EAS project for @ваше-ім’я/sleep-tracker?` | **Y** — створить проєкт у вашому акаунті й допише в `app.json` блок `extra.eas.projectId`. Залишайте його |
| `Generate a new Android Keystore?` | **Y** — буде створено ключ підпису й збережено в акаунті Expo |
| Пропозиція ініціалізувати git або закомітити зміни | можна погодитися (**Y**) або відмовитися — git не обов’язковий |

> **Ключ підпису (keystore) — це «паспорт» вашого застосунку.** Кожне оновлення має бути підписане тим самим ключем, інакше Android не встановить його поверх старої версії. EAS зберігає ключ у вашому акаунті; не видаляйте проєкт на expo.dev. Резервну копію ключа можна завантажити командою `eas credentials`.

Після відправлення з’явиться посилання на сторінку збірки. Термінал можна закрити — збірка триває в хмарі.

---

## 8. Дочекайтеся й завантажте APK

1. Відкрийте посилання зі збірки або зайдіть на [expo.dev](https://expo.dev) → ваш акаунт → **Projects** → **sleep-tracker** → **Builds**.
2. Статус пройде шлях *In queue* → *In progress* → *Finished*. На безкоштовному плані черга має низький пріоритет: від кількох хвилин до години й більше. Сама збірка триває 10–20 хвилин.
3. Коли статус *Finished*, на сторінці збірки з’являться кнопка завантаження (**Install** / **Download**) і QR-код.

---

## 9. Встановіть на телефон

Найпростіше — зробити все на самому телефоні:

1. Відкрийте сторінку збірки на телефоні (надішліть собі посилання в Telegram, Viber чи листом) **або** наведіть камеру на QR-код зі сторінки на комп’ютері.
2. Натисніть **Install / Download** і завантажте файл `.apk`.
   - Chrome може попередити, що файл такого типу здатний пошкодити пристрій, — оберіть «Все одно завантажити» (Download anyway). Це стандартне повідомлення для будь-якого APK.
3. Відкрийте завантажений файл (сповіщення про завантаження або застосунок «Файли»).
4. Android попросить дозволити встановлення з цього джерела (**«Встановлення невідомих програм»** / «Install unknown apps»). Увімкніть перемикач для браузера чи файлового менеджера, з якого відкриваєте файл, і поверніться назад.
5. Натисніть **Встановити**.
   - Google Play Protect може попередити про невідомого розробника або запропонувати перевірити застосунок. Торкніться **«Детальніше»** → **«Все одно встановити»** (назви кнопок трохи різняться залежно від версії Android). Це очікувано: застосунок не з Google Play, а ваш власний.
6. Натисніть **Відкрити**.

Інші способи: завантажити `.apk` на комп’ютер і скопіювати на телефон кабелем чи через Google Диск; або встановити з комп’ютера командою `adb install назва-файлу.apk` (потрібен USB-кабель, налагодження за USB і програма `adb`).

Після встановлення дозвіл на «невідомі програми» для браузера можна вимкнути назад.

## 10. Перший запуск

- Застосунок називається **«Трекер сну»**, іконка — місяць на фіолетовому тлі.
- На головному екрані натисніть **«Записати сон»** (або кнопку «+» внизу), оберіть години й хвилини барабанами чи швидкими кнопками, натисніть **«Зберегти»**.
- Хочете побачити, як виглядає статистика, не вводячи нічого? Натисніть **«Подивитися на прикладі»** — з’являться 90 демонстраційних днів. Їх позначено, і їх можна прибрати однією кнопкою: *Параметри → Прибрати демонстраційні дані*. Власні записи при цьому не зачіпаються.
- Усі дані зберігаються **лише на телефоні** й нікуди не надсилаються.

## Оновлення застосунку

Після змін у коді (або після вмикання нових можливостей, див. [ROADMAP.md](ROADMAP.md)):

1. Запустіть `eas build --platform android --profile preview` ще раз (новий пакет не створюйте — тільки команда).
2. Завантажте новий `.apk` і відкрийте його на телефоні — він встановиться **поверх** старого, **дані збережуться**. Видаляти старий застосунок не треба.

Профіль `preview` має `autoIncrement: true`: номер збірки (versionCode) зростає автоматично, тому Android завжди сприймає новий файл як оновлення.

Якщо Android пише «Застосунок не встановлено» — зазвичай це означає, що ключ підпису чи ідентифікатор пакета відрізняються від уже встановленої версії. У такому разі: зробіть [резервну копію](#резервна-копія-даних), видаліть старий застосунок і встановіть новий. Дані тоді відновлюються з копії.

## Резервна копія даних

Дані лежать у пам’яті застосунку. **Видалення застосунку (або «Очистити дані») стирає їх.** Автоматичній копії Android не варто довіряти — зробіть власну:

1. *Параметри → Дані → «Надіслати копію»*: оберіть, куди надіслати (нотатки, «Збережені» в Telegram, пошта). Копія — це звичайний текст.
2. Або *«Скопіювати копію»* і вставте текст у нотатки.
3. На новому телефоні (або після перевстановлення): скопіюйте цей текст → *Параметри → «Відновити з буфера обміну»*. Записи з копії додаються до наявних; якщо за якусь дату запис уже є, він замінюється значенням із копії. Решта записів не зачіпається.

Зробіть копію перед зміною телефона, перевстановленням і видаленням застосунку.

## Обмеження безкоштовного плану

За даними сторінки [expo.dev/pricing](https://expo.dev/pricing) на жовтень 2026 року, безкоштовний план EAS Build має такі обмеження:

- до **15 збірок Android на місяць** (лічильник оновлюється щомісяця);
- **низький пріоритет черги** — очікування може тривати довго;
- **45 хвилин** на одну збірку (цього вистачає з запасом).

Щоб не витрачати збірки даремно: перед кожною перевіряйте `npx expo-doctor` і `npm test`, а за потреби частих змін скористайтеся [швидкою розробкою](#швидка-розробка-з-перезавантаженням-на-льоту). Актуальні ліміти завжди дивіться на сайті.

Альтернатива хмарі — локальна збірка (`eas build --platform android --profile preview --local`). Вона потребує встановлених Android SDK та NDK і офіційно підтримується на macOS і Linux, але не на Windows. Для більшості випадків хмарна збірка простіша.

## Нове правило Google для «сторонніх» APK

Google запроваджує **верифікацію розробників Android**: із часом на сертифікованих пристроях встановлюватимуться лише застосунки від верифікованих розробників. Станом на жовтень 2026 року (за [офіційною сторінкою Google](https://developer.android.com/developer-verification)):

- **30 вересня 2026** захист почав діяти для користувачів у **Бразилії, Індонезії, Сінгапурі та Таїланді**;
- **глобально** — у **2027** році;
- для продвинутих користувачів передбачено «розширений режим» (advanced flow) встановлення неверифікованих застосунків;
- для любителів і тих, хто ділиться застосунком із рідними, Google пропонує **безкоштовний обліковий запис «обмеженого розповсюдження»**: до 20 пристроїв, без державних документів (потрібні лише Google-акаунт з двоетапною перевіркою і платіжний профіль). Деталі: [developer.android.com/developer-verification/guides/limited-distribution](https://developer.android.com/developer-verification/guides/limited-distribution).

**Що це означає для вас:** в Україні зараз нічого не змінюється, і встановлення власного APK працює як описано вище. Якщо у 2027 році обмеження дійдуть до вашого регіону, скористайтеся безкоштовним обліковим записом обмеженого розповсюдження або розширеним режимом. Правила Google можуть змінитися, тому перевіряйте офіційну сторінку.

## Швидка розробка з перезавантаженням на льоту

Збирати APK заради кожної дрібної правки довго. Для частих змін зробіть **development build** (одноразово) — окремий застосунок, який підключається до комп’ютера й оновлюється миттєво:

```bash
eas build --platform android --profile development
```

Встановіть отриманий `.apk` на телефон (так само, як у кроці 9), а потім на комп’ютері:

```bash
npx expo start --dev-client
```

Телефон і комп’ютер мають бути в одній Wi-Fi мережі. Відкрийте встановлений development-застосунок, і він підключиться до комп’ютера; зміни коду з’являтимуться на екрані телефона за секунди.

**Чому не Expo Go?** Готовий застосунок Expo Go працює лише з певною версією SDK (у магазині вона іноді відстає від найновішої) і не підтримує додаткові нативні модулі. А вони знадобляться, зокрема, для Health Connect (годинник). Тому в цьому проєкті Expo Go не використовується.

## Якщо щось пішло не так

**Як надіслати помилку.** На сторінці збірки на expo.dev відкрийте етап, що позначений червоним (*Install dependencies*, *Run gradlew* чи *Bundle JavaScript*), скопіюйте останні 30–40 рядків журналу й надішліть у чат.

| Проблема | Що робити |
|---|---|
| `npm install`: помилка `EBADENGINE` або «Unsupported engine» | Node.js занадто старий. Встановіть версію 22.13 або новішу |
| `npm install`: `ERESOLVE unable to resolve dependency tree` | Виконайте `npm install --legacy-peer-deps`, потім `npx expo install --fix` |
| `eas` «не розпізнано як команду» | Закрийте й відкрийте термінал заново; або користуйтеся `npx eas-cli@latest …` |
| PowerShell: «running scripts is disabled» | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` або запустіть `cmd` |
| Збірка падає на етапі *Install dependencies* | Майже завжди — несумісні версії пакетів. Виконайте `npx expo install --fix` і `npx expo-doctor`, виправте зауваження й запустіть збірку знову |
| Збірка падає на *Run gradlew* | Надішліть кінець журналу — це вже питання до коду або налаштувань |
| Збірка падає на *Bundle JavaScript* | Помилка в коді застосунку (JavaScript). Надішліть текст помилки |
| Повідомлення про вичерпання ліміту збірок | Безкоштовні збірки цього місяця закінчилися. Зачекайте нового місяця, збирайте локально (див. вище) або перейдіть на платний план |
| Android: «Застосунок не встановлено» | Див. [Оновлення застосунку](#оновлення-застосунку): ключ підпису чи пакет інші, або мало місця на телефоні |
| Android: встановлення заблоковано | Дозвольте «Встановлення невідомих програм» для браузера чи «Файлів» (крок 9) |
| Застосунок вилітає одразу після запуску | Зробіть знімок екрана чи опишіть, що бачите. Якщо побачили екран «Не вдалося запустити» з кнопкою «Спробувати знову» — перепишіть текст помилки з нього |
| Дати чи час «зсунулись» | Застосунок рахує за місцевим часом телефона; перевірте, що на телефоні правильний часовий пояс |

Корисні команди: `eas whoami` (хто увійшов), `eas build:list` (список збірок), `eas credentials` (ключі підпису), `npx expo-doctor` (перевірка проєкту).
